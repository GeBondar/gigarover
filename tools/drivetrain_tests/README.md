# Тесты ходовой GIGAROVER (прямой CAN, без ROS)

Диагностический инструментарий VESC-ходовой. Скрипты говорят с шиной напрямую
(python-can, протокол seeedstudio, USB-CAN на CH340) — тем же кодом, что и
`vesc_config_app`. Проверено на железе 27.07.2026.

**ВАЖНО: перед запуском любого CAN-теста остановите службы, владеющие
адаптером, иначе два писателя на одном порту дадут кашу:**

```bash
sudo systemctl stop rover-bringup rover-setup-web
python3 can_health.py
sudo systemctl start rover-bringup
```

Все CAN-скрипты сами находят живой порт перебором `/dev/ttyUSB*` (ждут
extended-id кадры — телеметрию VESC). CAN ID моторов зашиты в скриптах:
32, 34, 104, 114 (поменяете моторы — поправьте константы).

## Скрипты

| Скрипт | Что делает |
|---|---|
| `can_health.py` | **Основной тест ходовой**: профиль скоростей по ступеням (константа `STEPS`, сейчас 1500→2500→1200→800→1500 eRPM по 3 с), полная телеметрия в CSV (`/home/ubuntu/can_telemetry.csv`), сводка: частоты Status-сообщений, провалы линка, электрика/температуры, удержание цели, вердикт. |
| `reversal_test.py` | Постоянные +1500 eRPM всем моторам 12 с; ловит развороты (отрицательные eRPM), кадры с несуществующих CAN ID (порча приёма) и провалы; коррелирует развороты с провалами. |
| `coast_test.py` | Тест выбега: раскрутка → полная тишина передатчика → приём на свободном выбеге. Различает «помехи от тока моторов» и «проблемы при вращении как таковом». |
| `tx_flood_test.py` | Ломает ли передача приём на этом хосте — шлёт поток команд на несуществующий ID 99 (моторы не крутятся), сравнивает burst и paced отправку. |
| `ros_soak_test.py` | **Единственный ROS-тест**: публикует профиль в `/cmd_vel_teleop` (путь веб-морды) и сверяет фактические eRPM из `/diagnostics`. Службу НЕ останавливать — наоборот, `rover-bringup` должен работать. Запуск: `export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` + source обоих setup.bash. |
| `analyze_tel.py` | Разбор `can_telemetry.csv`: динамика eRPM по ступеням (min/avg/max/std, нули, duty). Запускать из каталога с CSV. |
| `analyze_gaps.py` | Разбор CSV: пики eRPM и хронология провалов >150 мс. |
| `analyze_steps.py` | Разбор CSV: провалы с привязкой к ступеням + удержание цели. |

## Безопасность

Каждый скрипт при любом выходе (включая Ctrl+C) шлёт всем моторам ток 0.
Цели ограничены 2000–2500 eRPM. Колёса при тестах должны быть вывешены,
либо будьте готовы к движению ровера (у `ros_soak_test.py` профиль с
нулевым суммарным смещением).

## Грабли, найденные этими тестами (история)

- USB-автосон Linux рвал обмен → отключён udev-правилом (99-gigarover.rules).
- Два одинаковых CH340 в системе → драйвер выбирал мёртвый порт; автопоиск
  драйвера теперь проверяет живой трафик (и эти скрипты тоже).
- «Провалы линка» в ранних версиях тестов были артефактом неограниченного
  дренажа RX в цикле — правильный паттерн: TX по расписанию 50 Гц +
  ограниченный дренаж (≤32 кадров) + короткий сон (см. can_health.py).
- Ниже ~900 eRPM ненастроенный sensorless VESC не держит обороты
  (лечение: Motor Wizard в VESC Tool; страховка: min_erpm в драйвере).
